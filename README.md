# Углублённый JavaScript: от prototype chain до event loop

Когда нужного поля нет у самого объекта, JavaScript может перейти к связанному с
ним объекту и продолжить поиск там. Последовательность таких объектов называют
prototype chain. В асинхронном коде за простым синтаксисом скрывается уже не путь
поиска, а порядок во времени: готовое продолжение `Promise` не выполняется прямо
посреди текущей работы, а становится отдельной готовой работой; event loop
определяет, когда она получит ход относительно других задач среды.

Большое приложение можно годами развивать, не разбирая эти механизмы, окружение
локальных привязок (lexical environment) и другие детали исполнения. Но именно
они становятся причиной самых неприятных ошибок: объект внезапно читает чужое
поле, модуль попадает в цикл, поток данных съедает память, а две одинаковые на вид
операции выполняются в разном порядке в браузере и Node.js.

Курс начинается с обычного чтения свойства и постепенно опускается ниже уровня
framework API. В финале вы соберёте и публично выпустите runtime для плагинов:
ему понадобятся управляемый граф импортов ECMAScript modules (ESM), отдельная
граница выполнения в Worker, отмена, ограничение потока при слишком быстром
источнике (backpressure), диагностика
и проверяемая поставка npm-пакета. Так каждая тема маршрута отвечает не на вопрос
«что ещё есть в языке», а на вопрос «какое поведение программы я теперь могу
объяснить, проверить и спроектировать».

Маршрут рассчитан на разработчика, который уже уверенно пишет JavaScript или
TypeScript для веба. Знание конкретного framework или архитектурной методологии
здесь не требуется. TypeScript используется
только там, где его типы можно стереть без изменения JavaScript-семантики; если
трансформация скрыла бы механизм, пример и упражнение остаются на чистом
JavaScript. Каждая карточка занимает 30–60 минут и заканчивается отдельным
проверяемым результатом, поэтому следующую тему не нужно начинать в тот же вечер.

Итого: 65 основных карточек и 10 карточек capstone.

Capstone собирает выбранные сквозные ветви — package surface, workers,
асинхронный lifecycle, backpressure и диагностику. Темы, которые не нужны plugin
runtime напрямую, не притягиваются в него искусственно: они заканчиваются
собственными проверяемыми результатами в тематических главах.

`function*` изучается как давно стандартизованный, но часто пропускаемый механизм,
а не как новинка последних лет. Действительно новые возможности 2023–2026
встраиваются в тематические главы и отдельно разбираются в главе 12 вместе с
процессом TC39 и матрицей поддержки.

## Среда

- Node.js 24 LTS — базовая среда выполнения;
- Node.js 26 — compatibility target, который проверяется отдельно;
- pnpm 10;
- TypeScript 7 в режиме `erasableSyntaxOnly`;
- Vitest для unit/integration checks;
- pinned Playwright Chromium для браузерных наблюдений, с отдельным install и
  launch preflight перед первой browser-карточкой;
- Rollup для главы о библиотечной сборке.

Подробная граница входных знаний и политика версий описаны в
[`curriculum/audience.md`](curriculum/audience.md).

## Начало работы

    pnpm install
    pnpm session:validate
    pnpm session:next

`pnpm session:check` запускает локальные автоматические проверки. Проверка
объяснений и соответствия rubric выполняется отдельным agent review. Подсказки и
reference solutions не лежат в рабочей ветке: runner раскрывает их по одному из
Git ref `course-support`.

## Личный прогресс

Проходите курс в личном fork и ветке `progress/<name>`. Официальный `master`
остаётся чистым, а `pnpm course:sync` подтягивает обновления upstream в текущую
progress-ветку, не отправляя ваши ответы в репозиторий курса.
